# 腾讯云函数版 Dify 代理

这个 Web 函数通过腾讯云提供的 HTTPS 函数 URL 转发到 Dify Cloud，保留现有网站聊天界面和 SSE 流式回复。Dify 密钥只放在腾讯云函数环境变量，不放进网页或 GitHub。

## 控制台部署

1. 登录腾讯云，进入「云函数 SCF」，新建 **Web 函数**，运行环境选 Node.js 18 或更新版本，地域先选广州，监听端口设为 `9000`。
2. 上传本目录中的 `deploy.zip`（已将三个部署文件放在压缩包根目录，并为 `scf_bootstrap` 保留执行权限）。
3. 在函数配置中设置环境变量 `DIFY_API_KEY`，值为 Dify 应用的 API Key。不要把密钥发给我或提交到仓库。
4. 将函数执行超时设为至少 130 秒，并启用公网「函数 URL」HTTPS 访问。
5. 打开函数 URL 后缀加 `/health`。应返回 `{"ok":true,"service":"GlobalNavigator Dify relay"}`。手机也可直接打开该地址检查是否能访问腾讯云端点。
6. 将函数 URL 后缀加 `/chat` 提供给网站维护者；网站的 `meta[name="dify-api-proxy"]` 要更新为该 `/chat` 地址，然后重新发布 GitHub Pages。

## 联通性判定

- `/health` 在手机上打不开：手机网络仍无法到达代理服务地址。
- `/health` 能打开，但聊天失败：检查腾讯云函数日志中的 Dify 上游状态。若广州地域无法访问 `api.dify.ai`，可在函数控制台尝试香港地域，再分别验证手机直连和 Dify API 出站访问。
- 聊天返回 401/403：检查 `DIFY_API_KEY` 是否为该已发布应用的 API Key。

函数 URL 和 Web 函数会按腾讯云 SCF 当前计费规则计费；部署前请查看控制台的地域价格和用量。当前限流是单实例内存限流，函数扩容后不是全局额度控制。
