# GlobalNavigator Dify 安全代理

GitHub Pages 只托管静态网页，不能安全保存 Dify 应用 API 密钥。这个 Worker 接收自定义聊天界面的请求，在服务端调用 Dify Chat API，再把流式回答原样传回网页。

## 首次部署

1. 在 Cloudflare Dashboard 的 [Workers 子域设置](https://dash.cloudflare.com/5afbec49b89dcbd91dc2cbf5ac5cc702/workers/onboarding) 中注册一个可用的 `workers.dev` 子域名。部署时 Cloudflare 自动尝试的 `dify-worker` 已被占用；可以尝试注册一个更独特的名字，例如 `globalnavigator-proxy-27749`。
2. 在电脑终端进入 `dify-worker` 文件夹，运行：

   ```powershell
   npx wrangler login
   npx wrangler deploy
   ```

3. 首次部署后，再运行：

   ```powershell
   npx wrangler secret put DIFY_API_KEY
   ```

   提示输入时，粘贴 Dify 应用的 **API 密钥**。密钥只会保存到 Cloudflare Secret，不要贴到网页源码、GitHub 或聊天中。保存 Secret 会发布一个含新密钥的 Worker 版本。
4. 将 Worker 地址加上 `/chat` 发给我，例如 `https://globalnavigator-dify-proxy.<你的子域>.workers.dev/chat`。我会把它写入网页的代理配置并重新发布。

## Dify API 密钥位置

在 Dify Cloud 打开对应应用，进入 **访问 API / API Access**，创建应用密钥。不要使用网页嵌入地址代替 API 密钥。

## 安全设置

- Worker 只允许 `https://afagasgfsagdi.github.io` 这个网站来源。
- 每个来源 IP 在每个 Cloudflare 边缘区域最多 12 次请求/分钟；Cloudflare 的内置限流是近似限流，不是全球严格额度。
- API 密钥由 `DIFY_API_KEY` Secret 保存，前端和 GitHub 中均不包含密钥。
- Cloudflare Workers Free 当前有每日请求额度；Dify 模型用量/套餐额度另计。

如果 Wrangler 提示 `namespace_id` 已被本账户其他 Worker 使用，在 `wrangler.jsonc` 中将它改为一个账户内唯一的整数，再运行部署命令。
